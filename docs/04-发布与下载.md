## 二、两条发布路线（选一条）

### 路线 A：主仓库 + Release Assets（**推荐**）

```
<主仓库>（放源码/文档/脚本，几十 MB）
  ├── README.md  docs/  boot-build/  rootfs-build/  tools/  dtb/  rootfs-config/
  └── Releases
        └── v2026-09-27
              ├── boot-umi-csot-ovf-wifi6-gpu-oc-final.img      （27 MB）
              ├── umi-system-opensource-2026-09-27.tar.gz       （1.98 GiB）
              ├── SHA256SUMS.txt
              └── RELEASE-NOTES.md
```

优点：克隆仓库很轻；二进制有独立的下载页与版本号；README 里直接写下载链接即可。

### 路线 B：独立 `releases` 仓库

另建一个仓库专门存二进制（例如 `<org>/umi-linux-releases`），主仓库 README 指向它。

**⚠️ 两条路线都必须注意**：

- **不要把 2 GB 的 tar.gz 提交进 git**。GitHub 对**单文件硬限制 100 MB**（超了必须 LFS），
  而且仓库体积会爆炸、克隆变慢。
- GitHub 对**单个 Release 附件上限 2 GiB**。本镜像 `1.978 GiB`，**余量只有约 22 MiB**
  —— 所以**不要再往这个 tar.gz 里塞东西**（多加一点日志/固件就可能超限）。
  一旦超过，用下面的拆分方式。

### 超限了怎么办：拆包

```bash
# 拆成 500 MiB 一片
bash tools/split-for-release.sh rootfs/umi-system-opensource-2026-09-27.tar.gz
# → rootfs/parts/umi-system-opensource-2026-09-27.tar.gz.part-aa / -ab / …

# 下载方合并（Linux/macOS）
cat umi-system-opensource-2026-09-27.tar.gz.part-* > umi-system-opensource-2026-09-27.tar.gz
sha256sum -c SHA256SUMS.txt        # 校验原始文件的 sha256
```

## 三、发布流程（务实版）

### 1）发布前检查清单

| ☐ | 检查项 | 怎么做 |
|---|---|---|
| ☐ | **镜像里不含个人信息** | 确认 `rootfs/` 内没有 WiFi 凭据、设备 MAC / 序列号、历史日志、个人 SSH 痕迹 |
| ☐ | **SHA256SUMS.txt 是最新的** | 改了任何文件就重算（命令见下） |
| ☐ | **首启安全提示在位** | README / `01-快速开始.md` 都必须有「先改密码 + 锁掉默认账号」 |
| ☐ | **默认不自启的服务仍不自启** | `umi-put`（8080 无鉴权）应保持手动启动 |
| ☐ | **许可证与出处写清楚** | `NOTICE-许可与出处.md`（内核/DTS 是 GPL-2.0，厂商二进制不含） |
| ☐ | **本发布不含厂商二进制** | `dtbo.img`、`a650_zap.mbn` 等不要打包进去 |
| ☐ | **CHANGELOG 写明本版改了什么** | 参考 `../CHANGELOG-2026-09-27.md` 的写法 |
| ☐ | **在真机上验过**：开机 + WiFi + GPU + 编解码 | `01-快速开始.md` §四 的验收清单 |

重算清单：

```bash
cd <本发布根目录>
# 注意：本目录同时是 git 工作树，必须排除 .git/（git 元数据不属于发布产物），
#       并保留首行注释头（sha256sum -c 会跳过 # 开头的行）。
{ echo '# UmiLinux v2026-09-27 —— 下载产物校验清单（sha256sum -c 自检）'; \
  find . -path ./.git -prune -o -type f ! -name SHA256SUMS.txt -print | sort \
    | xargs sha256sum | sed 's|  \./| *./|'; } > SHA256SUMS.txt
sha256sum -c SHA256SUMS.txt
```

### 2）打 tag 与 Release（GitHub CLI）

```bash
# 版本命名：v<日期>
TAG=v2026-09-27
REPO=misaka-link/umi-linux

git tag -a $TAG -m "UmiLinux v2026-09-27 —— 整机镜像 + 配套 boot（Debian 13 / 6.18.52 LTS）"
git push origin $TAG

gh release create $TAG \
    boot/boot-umi-csot-ovf-wifi6-gpu-oc-final.img \
    rootfs/umi-system-opensource-2026-09-27.tar.gz \
    SHA256SUMS.txt \
    --repo $REPO \
    --title "UmiLinux v2026-09-27" \
    --notes-file docs/RELEASE-NOTES.md
```

> 也可以用 `tools/publish-release.sh`（默认 dry-run，`--yes` 才真发）：
> ```bash
> REPO=misaka-link/umi-linux bash tools/publish-release.sh v2026-09-27
> ```

**RELEASE-NOTES 至少写这几条**：

- 这是**整机系统镜像 + boot**，不是"普通固件"，刷机前必读 `docs/01-快速开始.md`
- **首启必改 root 密码**（镜像默认密码在文档里公开）
- 支持机型的**面板必须是 CSOT**
- **必须保留原厂 `dtbo.img`**
- 已知限制（屏幕不驱动、无蜂窝、USB 默认 gadget 等，指向 README 的能力矩阵）
- sha256 列表

### 3）README 里的下载入口

在 README/`01-快速开始.md` 里给出**明确的一行下载命令或直链**，例如：

```bash
BASE=https://github.com/misaka-link/umi-linux/releases/download/v2026-09-27
curl -LO $BASE/boot-umi-csot-ovf-wifi6-gpu-oc-final.img
curl -LO $BASE/umi-system-opensource-2026-09-27.tar.gz
sha256sum -c SHA256SUMS.txt
```

## 四、下载方（使用者）怎么做

```bash
# 1) 下载两个产物 + 校验清单
# 2) 校验
sha256sum -c SHA256SUMS.txt
#    期望至少这两行 OK：
#    boot/boot-umi-csot-ovf-wifi6-gpu-oc-final.img: OK
#    rootfs/umi-system-opensource-2026-09-27.tar.gz: OK

# 3) 刷机 → 见 docs/01-快速开始.md
```

> 若你只下了两个二进制文件，也可以直接对表：
> boot 应为 `a7e4d341…`，rootfs 应为 `51f4b38d…`。

## 五、发版后的维护纪律

- 发布目录里的**任何文件被改动**，都要重算 `SHA256SUMS.txt`（见 §三 的清单命令）并同步更新 `docs/RELEASE-NOTES.md`。
- `boot/` 与 `dtb/`、`boot-build/` 必须**保持一致**：改了 DTS 就要重编 DTB、重建 boot，三处的 sha256 一起更新。
- `rootfs-config/` 是设备上 `/etc/default/*` 等关键配置的快照，改设备配置时记得回填。
- 版本命名沿用 `<类型>-<代号>-<日期>`（例：`umi-system-opensource-2026-09-27`）。
