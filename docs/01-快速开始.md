# 快速开始 —— 从零把这台小米 10 变成 Debian 服务器

> 目标读者：拿到本发布包、想把一台小米 10（`umi`）刷成纯 Linux 的人。
> 预计耗时：**刷机 20 分钟**（不含下载）；首次开机到能用约 **1 分钟**。
> **默认账号**：`root` / **`umi10linux`**（串口免密登录）；⚠️ 另有 **`armbian` / `armbian`**，
> 它在 `sudo` + `docker` 组 → **必须锁掉**。完整清单与加固步骤见 §三。
> 前置阅读：[`../README.md`](../README.md) 的「能力矩阵」与「安全与禁忌」。

## 〇、先确认三件事（不满足就别往下走）

| # | 检查项 | 怎么查 | 不满足会怎样 |
|---|---|---|---|
| 1 | **BootLoader 已解锁** | 开机出现"解锁"图标；`fastboot flashing get_unlock_ability` | 不能刷 `boot`/`userdata` |
| 2 | **面板是 CSOT** | 原系统里拨号 `*#*#6484#*#*` → CIT → **LCM Information** 看厂商前缀；或看 `androidboot.oled_panel_id` | 非 CSOT 需换 `boot-build/patch` 里的 `sms` 版 DTS 重编 DTB（本包默认给 CSOT） |
| 3 | **手上有原厂底包**（只要里面的 `dtbo.img`） | 例如 `umi_images_V12.5.10.0.RJBCNXM_.../images/dtbo.img` | **缺了就无法开机**（ABL 需要它做 overlay） |

**工具**：`adb` + `fastboot`（**务必用 MiFlash2020 自带的新版 fastboot**，旧版有 sparse 截断 bug）、
TWRP（用于解包 rootfs）。

## 一、⚠️ 刷机前必做：备份会丢就回不来的东西

**基带、IMEI、WiFi 出厂 MAC 一旦丢失，无法由本项目的任何文件恢复。**先备份这几项：

```bash
adb reboot bootloader

# 备份基带/校准分区（按实际分区名，A-only 设备一般如下）
fastboot getvar all 2>&1 | tee getvar-all.txt        # 先记录分区布局
for p in modemst1 modemst2 fsg fsc persist; do
    fastboot fetch $p backup-$p.img 2>/dev/null || echo "跳过 $p（不支持 fetch 就用 TWRP 备份）"
done
```

更稳妥的做法（推荐）：**用 TWRP 做一次全分区备份**到外置存储或电脑，或者至少确认手上有一份完整的官方固件备用。

**红线——以下分区永远不要 erase / format**：

```
modemst1  modemst2  fsg  fsc  persist  mdm1m9kefs1  mdm1m9kefs2  mdm1m9kefs3
```

## 二、全新安装（设备当前是 Android / 全新机器）

### 步骤 1：刷 boot 分区

```bash
adb reboot bootloader
fastboot flash boot boot/boot-umi-csot-ovf-wifi6-gpu-oc-final.img
```

> **A-only 设备**（本机）分区名就是 `boot`。
> 如果你的机器 `fastboot getvar current-slot` 显示 A/B 双槽，则用 `boot_a`（或 `boot_b`）。

### 步骤 2：刷回原厂 dtbo

```bash
fastboot flash dtbo <你的底包>/images/dtbo.img
```

> ★ **必须是原厂镜像**。`dtbo` 提供 ABL 需要的板级 overlay；替换成别的或留空 → 设备**秒进 fastboot**。

### 步骤 3：刷整机 rootfs（在 TWRP 里做）

`rootfs/umi-system-opensource-2026-09-27.tar.gz` 是**打包好的根文件系统**（不是 raw 镜像），
不能 `fastboot flash`，要在恢复模式里解包：

```bash
# ① 进入 TWRP
fastboot boot twrp-umi.img          # 或 fastboot flash recovery twrp.img 后按键进入

# ② 用脚本一键还原（自动校验 sha256 → 推送 → 设备端复校 → 解包）
bash tools/restore-system-opensource.sh
```

脚本会做的事：

1. 本地校验 tar.gz 的 sha256（期望 `51f4b38d…`）
2. 确认 `adb` 处于 **recovery** 状态
3. 推送镜像到 `/data/local/tmp/`，**在设备端再校验一次**
4. `tar xzf ... -C /data --numeric-owner -p` 覆盖整个 rootfs（即 `userdata` 分区）
5. 检查关键文件在位、确认不含 `/www`、`/var/lib/docker` 等，并 touch `/data/data/AUTO_RECOVERY_OFF`

> ⚠️ **破坏性**：整个 `userdata` 分区会被覆盖，原系统上的所有数据（含任何安卓数据）都会消失。
> 脚本会要求你输入 `yes` 二次确认。

如果脚本里的 `ADB` 路径不对，任选其一：

```bash
ADB=/usr/bin/adb bash tools/restore-system-opensource.sh      # 指定 adb
# 或者直接用 PATH 里的 adb（脚本在找不到时也会回退到 PATH）
```

### 步骤 4：开机

```bash
fastboot reboot     # 或直接长按电源键开机
```

**正常表现**（约 40~60 秒）：

- 电脑上出现 **"UsbNcm Host Device"** 网卡 → `ping 172.16.42.1` 通
- 出现一个 **USB 串口**（COMx）→ 打开就是 root shell（**免密**）
- 屏幕保持黑/灰（**正常**，面板被主动断电）

**这时候系统本体已经可用**：GPU / Vulkan、视频硬编解、息屏、充电区间控制、Docker 都已就绪，
不需要额外安装任何东西。**只有两件事要你亲自动手**：

| 必须做 | 为什么 |
|---|---|
| 改 `root` 密码 + 锁 `armbian` 账号 | 默认密码是公开的（而且 `armbian` 在 sudo/docker 组）→ 见 §三 |
| 配一次 WiFi | 镜像里**不含 WiFi 凭据**，不配就没有 WiFi（DHCP 客户端已配好） |

## 三、首启必做（4 步，别偷懒）

### 3.1 先说清楚：这个镜像里有哪些账号

用串口（COMx, 115200，**免密**）或 `ssh root@172.16.42.1`（密码 **`umi10linux`**）登进去。
以下是**镜像里实际的账号状态**（已逐项核对 `/etc/passwd`、`/etc/shadow`、`/etc/group`）：

| 账号 | 密码 | 能否登录 | 权限 / 说明 |
|---|---|---|---|
| **`root`** | **`umi10linux`** | ✅ 串口（免密）/ SSH / 本地 | uid 0；SSH 允许 root 密码登录 |
| **`armbian`** | **`armbian`** | ✅ SSH / 本地 | uid 1000，**在 `sudo`、`docker`、`adm`、`disk`、`tty`、`render` 等组** → `sudo` 即 root，**风险与 root 同级** |
| `www` | — | ❌ 已锁定 | 宝塔面板残留账号，无法登录 |
| `sync` | — | ❌ 已锁定 | 系统账号（shell 为 `/bin/sync`） |
| 其余 21 个系统账号 | — | ❌ 全部锁定 | `daemon`/`sshd`/`systemd-*`/`_apt`/`nobody` 等 |

> ⚠️ **串口是自动登录 root 的**（`agetty --autologin root`）→ 打开串口就是 root shell，不用密码。
> 所以"改密码"这件事**不能省**。

### 3.2 四步加固

```bash
# ① 改 root 密码 —— 镜像里的默认密码是本文档公开的，不改等于"人人可登"
passwd

# ② 锁掉 armbian 账号 —— 它带 sudo + docker 组，是第二把 root 钥匙
passwd -l armbian
#   确认真的不需要它也可以直接删掉：userdel -r arming

# ③ 唯一化 SSH 主机密钥（否则全世界共用同一对密钥）
rm -f /etc/ssh/ssh_host_*
ssh-keygen -A
systemctl restart ssh

# ④ 配 WiFi（交互式：扫描 → 选编号 → 输密码）
bash /root/wifi-connect.sh
```

**更彻底的做法**（推荐对外网暴露前做）：关掉密码登录，只留密钥：

```bash
sed -i 's/^PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config.d/99-umi.conf
systemctl restart ssh
```

**可选**：把 WiFi MAC 固定成你自己的（路由器做了 MAC 绑定时需要，见 [`02-使用指南.md`](02-使用指南.md) §四）。

## 四、验收清单（6 条命令全绿就算成功）

```bash
# 1) 系统健康：期望没有 failed 单元（历史遗留的 smartmontools 除外）
systemctl --failed

# 2) GPU：期望 /dev/dri/renderD128 与 card1
ls /dev/dri/
cat /sys/class/devfreq/3d00000.gpu/cur_freq

# 3) 视频编解码：期望 video0（解）+ video1（编）
ls /dev/video*

# 4) WiFi：期望 wlan0 存在且拿到 IP
ip -br addr show wlan0
iw dev wlan0 link

# 5) 电池与充电策略
cat /sys/class/power_supply/qcom-battery/capacity
journalctl -u battery-charge-limit -n 5 --no-pager

# 6) 顺手跑个真实负载（GPU 是不是真硬件）
vulkaninfo --summary 2>/dev/null | head -20      # 期望看到 Adreno (TM) 650
```

### 常见"看起来像失败但其实是正常"的项

| 现象 | 真相 |
|---|---|
| `dmesg` 里 `adreno ... error -22 initializing firmware a650_zap.mbn` + `GPU_SET Timeout` | **无害**，首次打开渲染节点时会重试成功 |
| `dmesg` 里 `qcom-pcie 1c00000.pcie: Phy link never came up`（约 1.95 s） | **无害**，WLAN 芯片 7.7 s 才上电，链路随后建立 |
| `systemctl --failed` 里有 `smartmontools` | 历史遗留，与本方案无关，可 `systemctl disable --now smartmontools` |
| 屏幕全黑 | **正常**，面板被主动断电 |

## 五、升级 / 重装（设备已经在跑 Linux）

**只换 boot（最常见，例如改了 DTB）**：

```bash
# 方式 A：设备在线，走 SSH
bash tools/../boot-build/build-boot.sh          # 先生成新镜像
# 然后把它 dd 到 boot 分区（见各发布版的 tools/flash-boot-*.sh 的写法：写前校验、写后回读）

# 方式 B：fastboot
adb reboot bootloader
fastboot flash boot <新的 boot.img>
fastboot reboot
```

> **只改 DTB 时不会碰你们的用户数据**，`boot` 分区每次都是整体覆盖。

**重装 rootfs**：重复 §二 步骤 3（会覆盖 `userdata`，用户数据全丢，先备份）。

## 六、回滚

| 想回到 | 怎么做 |
|---|---|
| **上一个可用的 boot** | 用本包 `boot/boot-umi-csot-ovf-wifi6-gpu-oc-final.img` 重新 `fastboot flash boot` |
| **原厂保守频率** | 设备上 `echo 'GPU_MAX_FREQ=587000000' > /etc/default/umi-gpu-maxfreq && systemctl restart umi-gpu-maxfreq` |
| **进了 TWRP 出不来、想正常进 Linux** | 清 BCB：`dd if=/dev/zero of=/dev/block/by-name/misc bs=1 count=32 conv=notrunc` |
